# v1.1.0 变更说明

- 版本：`1.1.0`
- 状态：开发/验证中

## 模块级执行超时与统一推送等待

- 所有模块详情页新增“执行超时时间”输入框，单位为秒。
- 每个模块可分别设置 `execution_timeout_seconds`，默认 `300` 秒。
- 允许范围：`0` 或 `10–86400` 秒；`0` 表示不施加执行超时。
- 模块执行超时直接使用该模块自己的值；未设置或清空时回落到 `300` 秒。
- 统一推送主触发时间改为每个模块的 `scheduled_at + execution_timeout_seconds` 的最晚值，默认等待 `300` 秒。
- 修改模块执行超时时间会同步影响该模块的统一推送等待时间。
- 统一推送主触发时间不再使用固定的 +1 分钟等待，而是使用模块超时时间。

## 验证

- 后端：317 passed / 0 failed
- mypy：0 errors
- OpenAPI：paths=43 / breaking=0

## 容器 UID/GID

- 镜像构建新增 `APP_UID` / `APP_GID`，默认 `10001`，并创建 `app` 用户。
- Compose 将 `PUID` / `PGID` 映射为构建参数；入口完成挂载目录 chown 后降权。

- 执行超时 `0`：不设置执行超时；统一推送主触发截止时间改用配置的超时兜底时间。

## 模块图标日志

- 成功解析模块图标不再写入系统日志；仅在读取/解析失败时记录 warning。

## 版本更新提示

- 网页端每次打开时请求 `/api/version`；服务端查询项目 GitHub 最新发布，成功缓存 1 小时、失败缓存 5 分钟。
- 发现远端版本高于当前版本时，左下角版本文本后显示红色提示圆点（带轻微脉冲）。
- 圆点直径为版本文本字号的 0.5em，即文字高度的 1/2。

## 第七轮审查修复

- 执行超时为 0 时，主触发截止时间使用 `max(scheduled_at, 超时兜底时间)`，不会早于模块计划执行时间。
- 全局 `MODULE_TIMEOUT` 在 Meta API 中标记为 deprecated；执行只使用模块级 `execution_timeout_seconds`。
